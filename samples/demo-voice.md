# 音色

**仓库不提供任何音色文件。**

音色是「用某个人的声音说话」的能力，克隆出来的模型就是那个人声音的可复现副本。
所以它既不能随代码分发（涉及声音权），也不该进 git（几十 MB 只是小事，
真正的问题是它会永久留在历史里）。

## 用系统自带音色（不用克隆）

`~/tts/` 目录下的 CosyVoice 自带若干基础音色，装上 TTS 服务就能用：

```bash
systemctl --user start meeting-tts
curl -s http://127.0.0.1:9880/voices | head -c 500
```

页面的「音色」下拉会列出实际可用的项。`sys:` 前缀的是内置音色，
人人可用；没有前缀的是克隆音色，按 `meta.owner` 归属到具体租户。

## 克隆自己的音色

要点只有两个：**参考音频**和**归属标记**。

### 1. 准备参考音频

| 要求 | 说明 |
|---|---|
| 时长 | **6–10 秒单段**最理想 |
| 内容 | 30–50 个字，日常口语（不要念稿、不要新闻腔） |
| 质量 | 安静环境、单人、无背景音乐；16k 以上采样率 |
| 格式 | wav / mp3 / m4a 都行 |

⚠️ **低于 5 秒效果会明显变差**：音素覆盖太少，模型只能学到音色轮廓，
学不到发音习惯 —— 听起来「像但不像你说话」。这**不是模型问题，是素材上限**。

### 2. 注册

`voice_register.py` 在**仓库根目录**（不在 `deploy/` 下）：

```bash
python3 voice_register.py --help        # 先看全部参数
```

典型用法 —— 从一段长录音里截 8 秒出来当参考音：

```bash
python3 voice_register.py \
  --name 我的音色 \
  --audio ~/recordings/me.m4a \
  --start 12 --end 20 \
  --profile 日常 \
  --owner me \
  --tts http://127.0.0.1:9880
```

| 参数 | 说明 |
|---|---|
| `--name` | 音色名，之后合成时用它 |
| `--audio` | 来源音频（wav/mp3/m4a） |
| `--start` / `--end` | 截取区间（秒）。**这就是解决「参考音太长不干净」的办法** |
| `--text` | 这段音频的逐字稿；不填会自动转写（要 ASR 可用） |
| `--channel` | 立体声取哪一路，默认 mix 下混 |
| `--profile` | 场景/语域：开会、日常、老家方言… |
| `--owner` | **归属租户，别留空** —— 空了就变成「人人可用」，越权保护失效 |
| `--list` | 列出已有音色 |

注册后会在 `~/tts/voices/<名字>/` 生成目录，并在 `meta.json` 里记下 `owner`。

### 3. 确认归属

```bash
ls ~/tts/voices/            # 看有哪些
cat ~/tts/voices/<名字>/meta.json | head -20   # 看 owner 字段
```

多租户下，别人看不到你的克隆音色（`/api/tts` 会对越权请求返回 403，且不回退到别人的音色）。
`owner` 为空的是老音色，为了兼容会放行给所有人 —— 新建音色请务必带上 owner。

## ⚠️ 别把音色放进仓库

- `~/tts/voices/` 在服务器上，**不在代码仓里**，这是对的，别改
- 需要备份就单独拷走（比如 `rsync ~/tts/voices/` 到另一台机器）
- 一旦误提交，`git rm` 不够 —— 历史里还有，需要重写历史（那是另一个话题，别顺手做）

## 相关

- 克隆与声纹的区别：声纹回答「这句话是谁说的」，音色回答「用谁的声音说」。
  两者用的是不同模型（`cam++` vs CosyVoice），互不影响。
- 方言场景的音色怎么配：见 [`DIALECT.example.md`](../DIALECT.example.md)
