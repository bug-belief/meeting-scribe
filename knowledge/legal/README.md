# 法律知识语料（L1 本地）

> ⚠️ **本目录不再存放法条正文。** 语料是「数据」，不是「代码」——
> 它由使用者按需生成、放在仓库之外，通过 `KB_LEGAL_PACK` 指向即可。
> 仓库里只保留**怎么获取**的脚本与说明（本文件）。

## 为什么把语料移出仓库

| 原因 | 说明 |
|---|---|
| 第三方内容 | 法条正文本身不受著作权保护（《著作权法》第五条排除法律法规等官方文件），但**汇编编排**可能有主张，仓库不装更干净 |
| 会过期 | 法规有修订与废止。仓库里放一份快照，读者无法判断它是不是最新的 |
| 体积 | 全量语料 41 MB，不应占用代码仓 |
| 一致性 | 仓库快照与线上索引包的条目数从来对不上，放着反而误导 |

现在：**仓库只有代码 + 获取脚本 + 说明**；语料由使用者自己生成，落在仓库外。

## 两条获取路径（按需要选）

### 路径 A：自抓法院 / 检察院 / 政府网页（量小、零第三方依赖）

适用：只想要少量常用法条，或想加自己的案例参考。

```bash
python deploy/fetch_legal.py                    # 抓 + 校验 + 写入 knowledge/legal/
python deploy/fetch_legal.py --add <URL>        # 追加一个交叉来源
```

收录规则（写死在脚本里的白名单，不靠自觉）：

1. 只收**法院 / 检察院 / 政府**域名；
2. **逐字原文**，不做改写、总结、标点统一；
3. 官方整编全文可直接收；零散摘引必须 **≥2 个独立站点逐字一致**；
4. 每条都记来源与抓取日期，可追溯。

产物是 `knowledge/legal/` 下的 Markdown（已被 `.gitignore` 忽略，不会误提交）。

### 路径 B：第三方开源法规数据库（全量，推荐）

适用：想要一个能真正检索的法条库。

两个上游，都是开源项目：

| 代号 | 项目 | 规模 | 许可 |
|---|---|---|---|
| **A** | `thu-lawyer/china-law-mcp` | 378 部 / 26,196 条，只收宪法·法律·立法解释，**条级时效更细** | MIT |
| **B** | `Ansvar/chinese-law-mcp` | 1,188 部 / 62,981 条，含 **611 部行政法规**，条文从官方 DOCX 提取 | Apache-2.0 |

```bash
# 先把两个上游的 SQLite 拿到本地（见各自仓库说明；npm 包 @ansvar/chinese-law-mcp 的 files 里含 data/database.db）
python deploy/build_legal_pack.py \
    --a-db ~/data/law-src/a-laws.db \
    --b-db ~/data/law-src/b-database.db \
    --out  ~/data/kb/legal-pack.json
```

**去重规则（关键，脚本已实现）**：

1. **B 内部**同一部法律常有多条 document 记录（`amended` / `in_force` / `not_yet_in_force`），
   每个版本各带一套完整条文 → **先按标题选一版**，否则《民用航空法》第 1 条会进库 4 次。
   选优顺序：`in_force` > `not_yet_in_force` > `amended`。
2. **A 与 B 之间**按「归一化法律名 + 条号」去重，**B 优先**（官方 DOCX 更权威）。
   归一化只削掉开头的「中华人民共和国」和空白，不做简称映射——简称映射靠猜会误合并，宁可有极少量重复。

实测合并结果：**46,268（B）+ 2,352（A 独有）= 48,620 条 / 963 部**，民法典 1,260 条全本。
每条带 `status`（现行有效 / 尚未生效 / 历史版本 / 已废止）、`law`、`article`、`doc_type`、`source`，
检索层可按时效过滤。

## 生成后怎么让服务用上

只需一个环境变量（写进 `.env`）：

```bash
KB_LEGAL_PACK=~/data/kb/legal-pack.json
```

`kb_bridge.py` 按 mtime **热加载**：换包不用重启服务。
包不存在或损坏时**静默降级为「无法检索」**，不会崩——所以缺语料不影响转写主流程。

其它相关开关：

| 变量 | 作用 |
|---|---|
| `KB_PACK` | 个人知识库索引包（另一套，与法条无关） |
| `KB_SCENARIOS` | 场景包 YAML |
| `KB_ENABLED=0` | 整体关闭检索注入 |

## 设计背景

三层供给（详见 `docs/产品化设计-v1-多租户与知识边界.md` 第 12 节）：

- **L1（本目录）**：本地法条原文，不联网也能查；
- **L2**：接专业法律数据 Connector 做实时检索；
- **L3**：让大模型只做解释、**不引条号**——避免它编一条不存在的法条。

铁律：**过滤发生在检索之前**（先算放行集合再排序），不是检索完再过滤。
