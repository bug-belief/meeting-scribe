## 9. 网页实时录音（阶段 2A）

手机浏览器打开一个页面，点一下按钮就开始录，边说边出字；点停止后自动生成带**说话人姓名**的转写稿和纪要。

### 9.1 两套链路，别混为一谈

```
实时：麦克风 → PCM16/16k → WebSocket → paraformer-zh-streaming（600ms 一块）→ 增量字幕
收尾：整段音频落盘 → 离线管线（segmentation 整段 ASR + cam++ 声纹 + ct-punc）→ 声纹库命名 → DeepSeek 纪要
```

流式模型只负责"立刻看到字"，它**不带标点、不做说话人分离**，准确率也比离线低一档
（实测同一段电话：实时把「违约责任」听成「违约则任」）。所以交付物一律以离线那份为准，
实时字幕只是让你确认"它在听"。

### 9.2 装依赖

```bash
cd ~/app
.venv/bin/python -m pip install fastapi "uvicorn[standard]"
.venv/bin/python deploy/prefetch_stream.py     # 下载流式模型，约 220MB
```

### 9.3 启动

```bash
# 前台调试
.venv/bin/python server.py --port 8848 --warmup

# 常驻（已装好的话）
systemctl --user enable --now meeting-web.service
systemctl --user status meeting-web.service
```

`--warmup` 很重要：流式模型首次加载要 20–30 秒，不预热的话用户点开始后要干等半分钟。

### 9.4 怎么访问

| 场景 | 地址 | 说明 |
|---|---|---|
| 服务器本机 | `http://127.0.0.1:8848` | 调试用 |
| 同一 Tailscale 网络 | `http://<你的内网IP>:8848` | 手机装 Tailscale 即可，**但 http 下浏览器不给麦克风** |
| **公网 https（现在用这个）** | `https://<你的域名>:8443/?k=<WEB_TOKEN>` | 已开启 Funnel，**手机不用装 Tailscale**；端口按实际 Funnel 配置填 |

必须 https：`getUserMedia` 只在安全上下文可用（localhost 除外）。Tailscale Funnel 是官方中继，
不用在路由器上开端口，也不需要域名和证书。

Funnel 已启用（2026-10-19 实测公网可达，DNS 解析到 Funnel 边缘节点而非 tailnet 内网地址）：

```bash
# 显式指定转发到本应用。不带目标时会占用默认 443，容易和同机其他站点冲突。
tailscale funnel --bg --https=8443 http://127.0.0.1:8848
tailscale funnel status           # 看当前映射；显示 "Funnel on" 即生效
tailscale funnel --https=8443 off # 关掉公网入口，退回 tailnet-only
```

Funnel 只允许 **443 / 8443 / 10000** 三个端口。**443 是默认端口、最容易被同机其他站点先占**，
所以这里用 8443，访问时**必须带端口号**：`https://<你的域名>:8443/`。
换端口只需重跑上面第一条命令（秒级生效，不用改任何代码或配置）。
`WEB_TOKEN` 是唯一门禁：链接带 `?k=` 校验通过后写 90 天 cookie，之后直接开首页即可。
**换口令**：改服务器 `.env` 的 `WEB_TOKEN` → `systemctl --user restart meeting-web.service`。

### 9.5 自测（不用麦克风）

```bash
ffmpeg -i 某段.mp3 -ac 1 -ar 16000 -c:a pcm_s16le /tmp/t.wav
.venv/bin/python tests/ws_smoke.py --wav /tmp/t.wav
```

输出会逐块打印增量字幕，最后打印归档路径。`--realtime` 参数按真实语速推送。

想验证**公网**链路（含 wss、Funnel、口令三件事），在任意一台能上网的机器上跑：

```bash
pip install websockets
python tests/ws_smoke.py --wav t.wav \
  --url "wss://<你的域名>/ws/live?k=<WEB_TOKEN>"
```

注意 wss 也要带口令，否则服务端直接以 4401 关闭连接。

### 9.6 已知限制

- **实时字幕没有标点和人名**：人名在停止后的离线稿里出现。
- **切后台/锁屏会断**：浏览器会挂起 WebSocket。要锁屏继续录必须做 App（Capacitor + 前台服务）。
- **首次连接慢**：模型没预热时要等 20–30 秒。
- **手机外放会自激**：用耳机，或把音量调小，否则麦克风会把 AI 的声音收回去。

### 9.7 电脑端：录系统声音 / 微信通话

页面底部有三个来源，手机只用得上第一个：

| 来源 | 能录到什么 | 说明 |
|---|---|---|
| 麦克风 | 说话的是谁就录谁 | 和手机一样 |
| 系统声音 | 电脑**正在播放**的一切 | 微信通话、腾讯会议、视频、网页播放器 |
| 双路分轨 | 麦克风 + 系统声音，**分左右声道** | 转写稿直接分「我 / 对方」，不用声纹猜 |

**系统声音怎么点**：点开始后浏览器会弹共享选择框 → 选「**整个屏幕**」→ 勾上「**同时分享系统音频**」→ 共享。
只有 Chrome / Edge（Windows）支持；Safari、Firefox、手机浏览器都不行。

**双路分轨为什么更准**：左声道是你麦克风、右声道是对方，服务端**按每句话在左右声道的能量**直接判人，
再对每一侧**单独做声纹聚类**——所以同一侧坐着两个人也能分开。
命名规则：麦克风侧依次「我、我2」，对方侧依次「对方、对方2」；声纹库认得的人用真名替换。
窄带、两人声音接近、重叠说话这些把声纹搞崩的场景，声道是硬证据——因为它来自两条物理上分开的流。
代价是**必须戴耳机**，否则麦克风会把对方的声音再收一遍，两边串音。

几个坑：

- 抓的是**默认输出设备**，播什么录什么。微信提示音、后台视频也会进转写稿。
- **蓝牙耳机通话会切 HFP（8k 单声道）**，音质掉一档，属于窄带。
- 从浏览器工具条点「停止共享」会正常收尾（前端监听 `ended` 自动 stop）。
- 想只录某个应用、不混进别的系统声音，浏览器做不到，得上原生采集器或 OBS + 虚拟声卡。

### 9.8 协议：浏览器怎么告诉服务端推什么

推第一块音频之前先发一条文本帧：

```json
{"type": "start", "source": "dual", "channels": 2}
```

`channels=2` 表示左右声道分开（左=麦克风、右=系统声音）；服务端据此调整切块大小
（60 ms 一块 × 声道数）、写立体声 wav，并在收尾时走「按声道判人」的分支。
服务端回一条 `{"type":"source", ...}` 确认。

命令行复跑（不需要浏览器）：

```bash
# 单声道
.venv/bin/python tests/ws_smoke.py --wav /tmp/t.wav
# 双声道：wav 是 2 声道时自动按 dual 推流
.venv/bin/python tests/ws_smoke.py --wav /tmp/stereo.wav
# 离线跑双路分轨（跳过实时，直接出稿）
.venv/bin/python transcribe.py --input /tmp/stereo.wav --output-dir work/x --dual --force
```

### 9.9 分身输出通道 `/voice`（阶段 3 前置探路）

**用途**：验证「网页里的音频能不能进微信麦克风」。CosyVoice2 上线前先用固定音频把通道打通，
免得模型做完了才发现卡在声卡上。

链路：

```
浏览器播放 → CABLE Input（虚拟声卡播放端）→ CABLE Output（录音端）→ 微信麦克风 → 对方
```

**前置**：装一块虚拟声卡（免费），装完必须重启。

```
https://vb-audio.com/Cable/          # 下载 New Package：VBCABLE_Driver_Pack45.zip
```

混音在网页里做（见 9.10），所以 **VB-CABLE 一块就够用**，不必再装 VoiceMeeter。

**三步操作**（页面 `https://<你的域名>/voice`）：

1. 点「开始检测」，允许一次麦克风（只为读到设备名，随即释放）
2. 下拉框选 **`CABLE Input`** —— 名字叫 Input 但它是播放设备，别选 Output
3. 点播放。然后去微信把麦克风设为 `CABLE Output`

**怎么验最省事**：别急着打电话。先给「文件传输助手」发一条**语音消息**——按住说话时
录的就是虚拟麦克风，松开后自己点开听。听到的是网页里那段音频，就说明整条链路通了。
再打电话给真人才验最后一环。

**接口**

| 路径 | 说明 |
|---|---|
| `GET /voice` | 操作页 |
| `GET /api/voice/samples` | 列出 `data/work/voice_samples/` 下的音频 |
| `GET /api/voice/sample?name=x.wav` | 取音频（只认该目录，拒绝路径穿越） |

**限制**：`setSinkId` 只有 Chrome / Edge 支持，Firefox、Safari 打不开这条路。
页面会自己检测并提示。

### 9.10 分身混音：真声 + 合成音同时进微信

微信一次只认一路麦克风。直接选 `CABLE Output` 的结果是「你能播分身，但自己说不了话」。
解决办法是在**进微信之前**把两路混成一路——这一步放在网页里做，不用装调音台软件。

| 声音 | 去向 |
|---|---|
| 你的真麦 | → 混音总线（分身说话时自动压到 −18 dB） |
| 分身合成音 | → 混音总线（给对方）**和** → 耳机（给你听） |
| 混音总线 | → `CABLE Input` → 微信麦克风 → 对方 |

**操作**（主页面，不是 `/voice`）：

1. 来源选「**双路分轨**」（要真声就必须有麦克风这一路）
2. 展开底部「**分身混音**」，勾选「混入微信麦克风」
3. 确认输出设备自动选中了 `CABLE Input`，点「试播」

微信那边麦克风仍然是 `CABLE Output`，不用改。

**三个设计决定，改代码前先看**：

- **混音总线不回接 worklet**。否则分身说的话会被自己的转写链路再听一遍，稿子里出现 AI 自语。
- **监听只挂合成音，不挂麦克风**。听自己说话有几十毫秒延迟会很难受，也没意义。
- **混音图只在录音会话期间存在**。`createMediaElementSource` 对同一个元素只能调一次，
  所以停止时整条链连同 `<audio>` 一起销毁，下次重建。

**坑**：

- 监听走的是**默认输出设备**。如果系统声音采集的也是同一台设备，分身的话会被当成「对方」录进转写稿。
  要么关掉监听，要么接受稿子里多出这几句。
- 必须戴耳机，外放会让麦克风把分身音再收一遍，形成自激。
- 微信的 AEC 会削弱合成音，合成音量给到 −6 dBFS 左右比较稳。
- 切歌/切设备后 `setSinkId` 可能抛 `AbortError`，页面的提示区会直接显示原因。

### 9.11 回放（旁听者视角）

录音结束后，结果面板顶部多一个播放器。双路分轨的录音会**混成一条单声道**再放——
听到的就是「坐在旁边的人」听到的全部内容：你、对方、分身，都在里面。

服务端按需转码并缓存：

```
processed/<归档目录>/<原始 wav>
        ↓ ffmpeg -ac 1 -ar 24000 -b:a 64k
work/_playback/<归档目录>.mp3
```

| 路径 | 说明 |
|---|---|
| `GET /api/archive/audio?dir=<归档目录名>` | 取回放音频（`dir` 只接受单层目录名，解析后必须落在 `processed/` 内） |

- **支持 Range**（返回 206），所以能拖动进度条，浏览器边下边播。
- 第一次请求会转码，54 秒音频约 0.3 秒；之后再取直接命中缓存。
- 原始 wav 一概不动，`_playback` 里的 mp3 可以随时清空，会按需重建。
- 页面底部还有「**回放上次录音**」，刷新页面后也能听最近一次（连带转写稿一起打开）。
