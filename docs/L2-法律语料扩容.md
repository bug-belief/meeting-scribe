# L2 法律语料扩容：从 526 条到 48,620 条（2026-10-19）

> 第 17、18 节解决了"查得到"和"不该说的别说"。这一节解决**"查得到的前提是库里得有"**——
> 之前库里只有《民法典》合同编 526 条，问劳动、交通、消费的事一律搜不到。

## 一、L2 要补什么

原规划三层：

| 层 | 内容 | 状态 |
|---|---|---|
| L1 | 本地法条，不联网可查 | ✅ 2026-10-19 落地（526 条合同编） |
| **L2** | **接专业法律数据库** | ✅ 本次落地（48,620 条） |
| L3 | 大模型只做解释，**不引条号** | 约束写进语料说明 |

L1 的短板很明显：`定金不退能退吗` 能查，`网购七天无理由怎么算` 查不到——不是检索不行，是库里没有。

## 二、选型：A 打底 + B 叠行政法规

| | 来源 | 覆盖 | 体积 | 许可 |
|---|---|---|---|---|
| **A** | thu-lawyer/china-law-mcp | 378 部 / 26,196 条（宪法·法律·立法解释） | 14.6 MB SQLite | MIT |
| **B** | Ansvar chinese-law-mcp | 1,188 部 / 62,981 条（含 **611 部行政法规**） | 71 MB SQLite | Apache-2.0 |

两份合并不是"多多益善"，是**互补**：实测重叠率 **91.0%**，A 真正独有的只有 2,352 条。
但这两千多条里有《生态环境法典》(1,240 条)、《宪法》(281 条)、社会救助法、医疗保障法、
耕地保护法等 2026 年新法，以及一批**立法解释**——B 全都没收。

反过来，B 有 A 完全没有的 611 部行政法规：《机动车交通事故责任强制保险条例》
《保障农民工工资支付条例》《工伤保险条例》——这些恰恰是口语问题最常落到的位置。

### 取数与坑

A：`pip download china-law-mcp` → wheel 3.3 MB，`laws.db` **在包内**，解压即用。

B：`data/database.db`（70 MB）在 GitHub 仓库里，但 **raw.githubusercontent.com 被重置**
（`curl: (35) Recv failure`）。三个镜像（ghfast / ghproxy / gitmirror / jsdelivr）全不通。
最后走 npm：包名 `@ansvar/chinese-law-mcp`，`files` 字段里明确含 `data/database.db`，
从 **npmmirror** 拉 tarball —— 33 MB / 4.6 秒（9.4 MB/s）。

```bash
curl -L -o clm.tgz https://registry.npmmirror.com/@ansvar/chinese-law-mcp/-/chinese-law-mcp-3.0.0.tgz
tar xzf clm.tgz    # → package/data/database.db
```

## 三、去重：两个必须处理的坑

### 坑 1：B 内部同一部法律有多条记录

`legal_documents` 里《民用航空法》有 4 条记录（`amended` / `not_yet_in_force` /
`amended` / `in_force`），**每条各带一套完整条文**。62,981 条里有近 1.7 万条是这种版本重复。

选优顺序：`in_force` > `not_yet_in_force` > `amended`。去重后 **930 部 / 46,268 条**。

### 坑 2：A 与 B 的重叠

键是「归一化法律名 + 条号」，**B 优先**（官方 DOCX 提取、零 LLM 生成）。
归一化只削掉「中华人民共和国」前缀和空白，**不做简称映射**——「民法典」↔「民法」
这种靠猜会误合并，宁可有极少量重复。

结果：B 46,268 + A 补 2,352 = **48,620 条 / 40.8 MB JSON**。

| 效力 | 条数 | | 类型 | 条数 |
|---|---|---|---|---|
| 现行有效 | 48,165 | | 法律 | 25,062 |
| 尚未生效 | 268 | | 行政法规 | 23,308 |
| 历史版本 | 138 | | 宪法 | 143 |
| 已废止 | 49 | | 部门规章 | 107 |

## 四、检索质量的三个真问题

铺到 4.8 万条之后，原来在 75 条个人 KB 上看不出来的毛病全暴露了。

### 问题 1：BM25 写成了「取最大值」而不是「求和」

原实现：

```python
if rec is None or s > rec["chunk_score"]:
    best[eid] = {...}          # ← 只留最高的那个 token 的分
```

等于一份条文命中 5 个词，分数只算最高的那一个。实测后果：
「违约金太高能少给吗」时，《民法典》585 命中「违约」「约金」两个词，
却输给《刑法修正案（八）》只命中「能少」一个词——因为「能少」更稀有，IDF 更高。

改成先在 chunk 内**累加**所有 token 的贡献，再在条目内取最高分的那段。

### 问题 2：跨词边界拼出来的碎片

二元组会把「能少给」切成「能少」「少给」，而「不能少于」在刑法减刑条款里反复出现。
这类碎片 IDF 极高，纯粹在带偏。

在 `STOP_BIGRAMS` 里补了「能少 / 少给 / 太高 / 高能 / 金太 / 给吗 / 太多 / 多少 /
不够 / 咋办 / 能不 / 不能」。**只修好了错的那条，另外四个查询排序一字未变**。

### 问题 3：口语召不回法言法语

「买到假货能退一赔三吗」→ 首位《监狱法》
「外卖吃出异物能索赔吗」→ 首位《反食品浪费法》

不是排序坏了，是**召回阶段候选里就没有正确条文**——法条写的是「欺诈」「混有异物」。

引入 `LEGAL_SYNONYMS` + `LEGAL_COOCCUR` 规则表（取自 A 的 `retrieval.py`，MIT，
删掉了「赔偿→损害」这类会自反误伤的宽泛项，补了消费维权几条），命中 key 时把右侧词
并入查询。**权重 0.5 不是 1.0**：扩展词是猜的，不能压过用户原话。

扩展必须进 BM25 参与召回（只用于重排没用，候选集里根本没有），这一点实测对比过：
扩展进 BM25 首位 10/16，只进重排 8/16。

### 重排公式

两段式：BM25 召回 top 60，再按 A 的方案重排：

```
score = BM25/最大值 + 0.45×查询词覆盖率 + 0.25×扩展词覆盖率 + 0.55×最长公共子串/12
```

归一化是为了消掉绝对分数差异（条文短，BM25 天然偏低）。最长公共子串是纠正
"稀有碎片压过真词"的关键信号：「违约金」3 字 vs 「能少」2 字。

## 五、实测

17 条口语化查询，人工核对首位是否命中期望法律：

| | 首位命中 | top3 命中 |
|---|---|---|
| 改之前 | 7/16 | — |
| **改之后** | **10/17** | **14/17** |

几个代表：`退一赔三 → 消保法第 55 条`（正是三倍赔偿条款）、`违约金 → 民法典 585`、
`假货 → 消保法`、`异物 → 食品安全法`、`工伤 → 工伤保险条例`。

**已知不足**（不掩饰）：
- 「交通事故责任怎么认定」首位是《海上交通安全法》，该出的是《道路交通安全法》第 73 条；
- 「高空抛物谁负责」首位是《刑法修正案（十一）》第 33 条（其实也是对的，高空抛物罪），
  但《民法典》1254 掉到第 5；
- 「个人信息被泄露」首位是《反电信网络诈骗法》，《个人信息保护法》在 top3 内但不在首位。
- 规则表是手工的，覆盖率有限，生僻表述仍会漏。

对比旧包（526 条合同编）：**旧包在这些领域是 0 条**，所以净收益仍然是正的。

不该影响服务起来。

## 七、运维

```bash
# 重建（两个源库留在 ~/data/law-src/）
.venv/bin/python deploy/build_legal_pack.py \
    --a-db ~/data/law-src/a-laws.db \
    --b-db ~/data/law-src/pkg/package/data/database.db \
    --out  ~/data/kb/legal-pack.json

# 只留现行有效（想更省内存/更严时）
... --only-status 现行有效,尚未生效

# 测试
.venv/bin/python tests/test_legal_pack.py     # 61 项，含 5 处反向对照
```

**回滚**：`~/data/kb/legal-pack.json.bak-*` 是旧包，改回来重启即可。
老包缺 `scopes` 字段会被当 `general` 全放行——所以旧包只在回滚时用，别长期混跑。

## 八、顺手修掉的一个假绿

`test_kb_search` 的「包不存在返回空」用例只设了 `KB_PACK`，**没隔离 `KB_LEGAL_PACK`**，
于是 `load_legal()` 去读了线上真的法条包。旧包 526 条命不中测试里的问题，测试一直是绿的；
扩到 4.8 万条后法条挤进注入，预算断言当场爆掉，连带崩了 3 项。

这是测试隔离缺陷，不是产品 bug——修法是**把法律包显式指到不存在的路径**，
而不是放宽断言。同类坑在 `test_scenario` 里已经踩过一次，这次是第二处。
