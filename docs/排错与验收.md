## 12. 排错表

| 现象 | 原因 | 处理 |
|---|---|---|
| `找不到 ffmpeg` | PATH 未生效 / 用了 sudo 的环境 | `.env` 写绝对路径 `FFMPEG_BIN=/usr/bin/ffmpeg` |
| 模型下载卡住 | ModelScope/HF 网络 | `FUNASR_HUB=ms`；或 `export MODELSCOPE_CACHE=~/models` 后重试 |
| `CUDA out of memory` | `batch_size_s` 过大 | 降到 120/60，或 `ASR_DEVICE=cpu` |
| 全是 `Speaker 1` | 未启用 `spk_model` | 确认 `FUNASR_SPK=cam++`，且 funasr ≥1.2 |
| 说话人乱跳 | 抢话/远场/回声 | 手机尽量靠近、避免外放；调 `DIAR_WINDOW_MS`（默认 3000）与 `DIAR_MIN_SIM`。**不要**试 `FUNASR_SPK_MODE`——该变量已移除，说话人分离由 `diarize.py` 自研实现，FunASR 内置切句两种模式都实测有 bug（见 `diarize.py` 抬头） |
| 文件不触发 | 扩展名不在白名单 / 同步工具临时文件 | 检查 `AUDIO_EXTS`；等 60s 兜底扫描 |
| 反复处理同一文件 | `state.json` 被删 | 正常情况勿删；`work/state.json` 是去重依据 |
| `401 / 402 / 余额不足` | Key 失效或计费不足（**两者处置不同**） | 先看界面红字属于哪一类，再查 **§12.1 分类表**；程序重试 3 次后保留转写稿，数据不丢 |
| 纪要丢了但转写还在 | 云端失败 | 归档目录里 `report.md` 会写明重跑命令 |
| 中文乱码（Windows） | 控制台 GBK | 程序已强制 UTF-8；仍乱码则 `chcp 65001` |
| 端到端脚本永远「0 行 / 通过」 | `websockets ≥14` 没有 `recv_nowait()`，异常被 `except: pass` 吞掉 | 改成后台 `async for ws` 读消息（照抄 `tests/ws_noise_e2e.py`）。这条坑吃掉过一次真实回归 |
| 面板上冒出没说过的话 | 流式模型在底噪上"续写" | 见 10.16 的两道闸门；看日志里的「丢弃噪声行」 |
| 我说了不算，对方一句「助理」就触发 | 唤起档位是 `guest/open`，或旧版没判 `who` | 见 10.18；默认 `strict` 只听我的 |
| 关麦后助理不接话 | `strict` 档不认对方；代班要切 `proxy` | 见 10.18 |
| 收藏了但音频还是被删 | 清理没读到 `.favorite`（手工挪过目录 / 权限） | `ls <归档>/.favorite`；`retention.py` 预演看它是否列在「收藏豁免」 |
| 归档仓里找不到旧路径 `meetings/` | 已改成 `tenants/<owner>/meetings/` | 见第 15 节；git 历史里还能查旧路径 |
| 接话/提词红字写着「AI 服务…」 | 见下面 §12.1 的错误分类表 | 按表里那一行的「处理」走；界面只给一句人话，原文在 `logs/summarize.log` |

### 12.1 LLM 错误分类（接话 / 提词）

> 真源是 `llm_errors.py` 的 `CATALOG`，本表是它的**人读镜像**。
> 改分类时**两处一起改**，并给 `tests/test_llm_errors.py` 补一个正例 + 一个反例。

**为什么要有这张表**：上游（OpenAI 兼容服务 / 自建网关）出错时给的是一大段英文 JSON
（例如 `litellm.BadRequestError: OpenAIException - Insufficient Balance ...`），
直接透到界面上等于什么都没说。而**不同错误的处置动作完全不同**——
余额不足要充钱、密钥失效要换 key、限流只要等一下、服务没起要去看进程。
所以先归类，再给「一句人话 + 一条建议」。

| kind | 界面显示（人话） | 界面建议 | 真实处理 |
|---|---|---|---|
| `no_balance` | AI 服务余额不足 | 转写和归档不受影响；充值后立即恢复 | 给 DeepSeek 充值（**不用重启服务**） |
| `bad_key` | AI 服务鉴权失败（密钥无效或已过期） | 检查 `LLM_API_KEY` | 换 key；如果走的是自建网关，这把要填**网关的 key**，不是上游 key |
| `rate_limit` | 请求太频繁，被限流了 | 隔一两分钟再试 | 降低调用频率；提词有 1.2s 防抖 |
| `quota` | AI 服务调用额度已用尽 | 额度恢复或换 key 后可用 | 查套餐/配额 |
| `unreachable` | 连不上 AI 服务 | 先确认 `LLM_BASE_URL` 指向的服务在跑、端口对得上 | `curl -s -o /dev/null -w '%{http_code}' $LLM_BASE_URL/models`；**这是「连不上」，不是「慢」** |
| `timeout` | AI 服务响应超时 | 重试一次；持续超时看长尾延迟 | 查 `logs/`；实测长尾能到 10s 以上，别只测一次就下结论 |
| `model_missing` | AI 服务没有可用的模型 | 检查 `LLM_MODEL` 是否服务端真有这个模型 | 模型名拼错，或这把 key 无权访问该模型/模型组 |
| `empty` | AI 返回了空内容 | 通常是 max_tokens 被思考链吃完 | **加大 `max_tokens`（≥1024）**，别当成内容过滤 |
| `unknown` | AI 服务出错 | 详情见 `logs/summarize.log` | 原文已截断到 160 字，看日志拿全量 |

**两条容易搞错的边界**（`test_llm_errors.py` 用反例锁住了）：

1. `connection timeout` / `ConnectTimeout` 归 **`unreachable`**，不是 `timeout`。
   前者是「连都没连上」（端口没开 / DNS 不通），该去看进程；
   后者（`ReadTimeout` / `read timed out`）才是「连上了对面不回」，那才重试。
2. 402 与 401 同时出现时归 **`no_balance`**——402 是更具体的原因。

**真实案例**：上游账户余额耗尽那一刻起，**所有** LLM 调用开始返回 402。
转写/分离/归档**不受影响**（本地 ASR），只有纪要与接话/提词失败。
当时界面显示的是原文长串，用户无法判断该做什么 —— 这就是本节存在的原因。

## 13. 验收清单

- [ ] `python config.py` 能打印配置，路径都指向预期目录
- [ ] `python transcribe.py --input 样例.m4a` 输出含 `Speaker N` 与时间戳
- [ ] `python summarize.py --dry-run` 显示 direct 或 map-reduce 分块合理
- [ ] 真实 API 生成 `report.md`，front-matter 里能看到 token 消耗
- [ ] 手机录一段 → 自动出现在 `processed/`，且带音频+转写+纪要
- [ ] `systemctl restart meeting-watcher` 后历史文件不被重复处理
- [ ] 故意传一个损坏文件 → 日志报错但不退出，文件最终进 `processed/_failed/`
- [ ] 归档页显示 `ID M...`，点一下能复制；`/api/meeting?id=` 能拿回音频、稿子、纪要
- [ ] 面板里助理的话是草稿原文，说到哪算哪（已说正常色、未说压灰），不再出现「对方」
- [ ] 转写稿里助理的天气数字与播报日志逐字一致，不会出现「一七度」「六和九」
- [ ] 音色下拉同时有 `zhangsan`（普通话）和 `张三 · 方言`，两个都能合成
- [ ] 音色下拉分两组：我的声纹 / 电脑声音；选电脑声音后助理标签变成「助理（电脑声音）」
- [ ] 实时面板和转写稿里，同一个人始终同色，助理固定紫色并带 `AI` 角标
- [ ] 没人说话时面板不冒字（日志里能看到「丢弃噪声行」，面板上干干净净）
- [ ] `.venv/bin/python tests/run_all.py` 一次性出表：**合计通过 350 / 失败 0 / 基线 350**
- [ ] `tests/ws_noise_e2e.py` 拿真实录音的底噪片段跑出 0 行、说话片段跑出 1 行
- [ ] `node tests/wake_decision_test.js` 16 项通过（含反向对照：故意去掉 strict 限制必须报错）
- [ ] 唤起切 `strict`：对方说「你们有助理吗」不触发；我说「语音助理」触发
- [ ] 关掉「🔊 出声」后仍能拿到文字（面板标「只听不说」），但扬声器没有声音
- [ ] 点 ☆ 收藏 → `ls ~/data/tenants/me/processed/<归档>/.favorite` 存在；再点变回 `☆ 收藏`
