# 架构与选型（数据流 · 文件结构 · 模型 · 省 Token）

> 首次整理：原根目录 `README.md` 第 0 / 1 / 2 / 4 / 7 节（1,515 行版本，2026-10-20 拆分）。原文逐字保留，未改写。

## 0. 先看结论：技术可行性与选型

| 环节 | 选型 | 结论 | 说明 |
|---|---|---|---|
| 手机录音 | 系统自带录音机（m4a/mp3） | ✅ | 无需改格式，ffmpeg 统一转 16k 单声道 |
| 同步 | Syncthing | ✅ | 开源、点对点、不走云；iOS 需用 Möbius Sync（见第 8 节） |
| 触发 | watchdog 事件 + 定时兜底扫描 | ✅ | 「大小/mtime 稳定 N 秒」才处理，规避半截文件 |
| 转写（中文） | **FunASR**：`paraformer-zh` + `fsmn-vad` + `ct-punc` | ✅ 推荐 | 中文 CER 明显优于 Whisper，CPU 可跑，一条流水线出结果 |
| 说话人分离 | FunASR 内置 `cam++` 声纹 + 聚类 | ✅ | 一次 `generate()` 就返回 `sentence_info`（含 `spk`/`start`/`end`），**无需 HuggingFace 授权** |
| 转写（多语种） | WhisperX + pyannote | ⚠️ 可选 | 英文/多语种更强，但 pyannote 模型需 HF 授权，建议 GPU |
| 纪要生成 | OpenAI 兼容 API（DeepSeek `deepseek-flash`） | ✅ | 只发文字，1 小时会议约 1.2 万输入 token |
| 归档 | `processed/<日期>_<名称>/` | ✅ | 音频 + 转写 + 纪要 + meta 一起归档，哈希去重防重复处理 |

**成本量级**：1 小时中文会议 ≈ 1.5~2 万字转写 ≈ 1.2 万 tokens 输入；单场云端费用在「分」的量级（以 DeepSeek 官网实时价为准），本地 ASR 完全免费。

**三个必须知道的边界**（不是 bug）：

1. 说话人只能标成 `Speaker 1/2/3`，**不会自动识别真实姓名**（可在纪要里让模型标注「待确认」）。
2. 多人抢话、远场拾音、音质差时，声纹聚类会串人；这是所有开源方案的共同短板。
3. 超长音频若手动切片（`ASR_SPLIT_MINUTES>0`），说话人编号不跨片连续。

## 1. 数据流

```
手机录音机 (m4a)
      │  Syncthing 自动同步
      ▼
./audios_inbox ──► watcher.py（watchdog 监听 + 60s 兜底扫描）
                        │  稳定性判定：大小/mtime 连续 8s 不变
                        ▼
                  pipeline.py
                        │ ① ffmpeg → 16k 单声道 wav
                        │ ② transcribe.py（FunASR / WhisperX）→ transcript.md + json
                        │ ③ summarize.py（DeepSeek）→ report.md
                        │ ④ 归档 + 写入 work/state.json（哈希去重）
                        ▼
        ./processed/2026-01-01_周会/
            ├── 周会.m4a            ← 原始音频
            ├── transcript.md      ← 带时间戳+说话人
            ├── transcript.json    ← 结构化分段
            ├── report.md          ← 会议纪要
            └── meta.json          ← 时长/哈希/耗时
```

## 4. 模型选择建议

| 场景 | 推荐配置 | 理由 |
|---|---|---|
| 中文会议（默认） | `paraformer-zh` + `fsmn-vad` + `ct-punc` + `cam++` | 中文准确率高，标点完整，自带说话人 |
| 追求速度 / 带情绪标签 | `model="iic/SenseVoiceSmall"` | 非自回归极快，CPU 也接近实时；但时间戳粒度粗，`spk` 会回退到 VAD 段对齐 |
| 中英混杂 / 外语会议 | WhisperX `large-v3` + pyannote | 多语种更强；需 `HF_TOKEN` 且要在 HF 上同意 pyannote 模型条款 |
| 只要文字不要谁说的 | 任意 ASR，`FUNASR_SPK=` 留空 | 省 30% 左右时间 |

切换后端只需改 `.env` 的 `ASR_BACKEND`，代码无需改动。

## 7. 省 Token 的设计（你关心的重点）

1. **分流**：`SUMMARY_DIRECT_CHARS=12000` 以内单次调用；超过才分块，避免所有会议都走多轮。
2. **Map 限长**：每块只产出「议题/结论/待办/关键数字」四类，`max_tokens=700`，比让它写散文省一半输出。
3. **报告头本地拼**：日期、时长、说话人数、模型名由 Python 写，模型只产出正文。
4. **Prompt 只说规则**：`prompts.py` 里 System Prompt 约 300 token，不讲背景、不要客套。
5. **分层归并**：块数多时先做二级归并（最多 2 轮），防止 reduce 输入无限膨胀。
6. **温度 0.3**：纪要要稳定，不需要创造力。
7. **实测账**：每份纪要的 `tokens: prompt=… completion=…` 写在 `report.md` 的 front-matter，直接可核对。
